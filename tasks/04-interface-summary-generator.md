## Goal
Stand up `scripts/regen-interfaces.sh` — the script that produces `docs/interfaces/<subsystem>.md` summaries from the canonical schema artifacts (`.proto`, `migrations/*.sql`, pub Rust traits). After this task, every later task can be verified for "did the public interface drift?" by running `regen-interfaces.sh && git diff --exit-code docs/interfaces/`. This is decision D4 in `tasks/README.md` made executable.

## Inputs to read before starting
- `tasks/README.md` §3 (D4 — schema files canonical, generated summary first to read) and §5 (verification model — silent-drift backstop).

## Scope — in
- Create `scripts/regen-interfaces.sh` (executable) that:
  1. Walks `proto/**/*.proto` and writes `docs/interfaces/proto.md` containing, per file: the package, each `message` name with its field list, and each `service` name with method signatures.
  2. Walks `crates/persist/migrations/*.sql` and writes `docs/interfaces/schema.md` containing, per migration file: the file name, each `CREATE TABLE` statement (verbatim), each `CREATE INDEX` statement.
  3. Walks `crates/*/src/api.rs` (a conventional path each crate uses for its pub-facing module — declared here as the contract) and writes `docs/interfaces/rust-api.md` containing the `pub trait` and `pub struct` declarations with their signatures.
- The script is deterministic: same inputs → byte-identical outputs. No timestamps, no random IDs.
- Each generated file starts with a header: `<!-- AUTO-GENERATED by scripts/regen-interfaces.sh — do not edit by hand. -->`.
- Create the `docs/interfaces/` directory with a placeholder `.gitkeep`.
- Generate the three interface files for the current (empty) state of the repo. They will be near-empty — that's fine.
- Add the script invocation as a CI step in `.github/workflows/ci.yml` (Linux only):
  ```yaml
  - name: Check interface summaries are up to date
    run: |
      ./scripts/regen-interfaces.sh
      git diff --exit-code docs/interfaces/
  ```

## Scope — out
- No GraphQL/OpenAPI extraction (not used in V0.1).
- No automatic linking to design-doc sections (could be a V1.0 polish task).
- No HTML rendering — pure markdown.

## Public interface this task locks
- Path: `scripts/regen-interfaces.sh` and `docs/interfaces/proto.md|schema.md|rust-api.md` are the canonical names; later tasks reference them.
- Convention: every crate's pub-facing module is at `crates/<crate>/src/api.rs`. Code that wants to be "public interface" lives in that file. Internal modules don't.
- The "no hand edits" rule: changes to `docs/interfaces/*.md` must come through regeneration.

## Implementation notes
- Implement in plain bash + `grep`/`sed`/`awk` if feasible — keeps zero deps. If parsing `.proto` correctly is too painful in bash, fall back to a small Python or Rust helper, but stay within deps that are already on a stock CI runner.
- For proto parsing, you can use `prost-build`'s own parser by writing a small Rust helper crate (`tools/regen-interfaces`) — that's cleaner than bash regex if you want to take the time. Either approach is acceptable.
- For SQL: just grep for `CREATE TABLE` / `CREATE INDEX` lines and indent them. Don't try to parse full SQL.
- For Rust traits: grep for `pub trait ` and `pub struct ` lines + their containing block. A simple awk one-liner that captures the brace-balanced region is sufficient.
- Sort outputs deterministically (by file path, then by declaration order within file).

## Verification
1. `bash -n scripts/regen-interfaces.sh` → no syntax errors.
2. `./scripts/regen-interfaces.sh` → exits 0; creates/updates `docs/interfaces/{proto,schema,rust-api}.md`.
3. `./scripts/regen-interfaces.sh && git diff --exit-code docs/interfaces/` → no diff on a clean run (deterministic).
4. Manually add a fake `pub trait Foo {}` to a crate's `src/lib.rs`; rerun the script; confirm `rust-api.md` changes. Revert the fake change.
5. `shellcheck scripts/regen-interfaces.sh` → 0 errors.
6. CI workflow includes the interface-check step and it passes on a clean PR.

## Handoff Notes (fill in when finishing)
- **Drift from plan:**
  - **No `docs/interfaces/.gitkeep`.** The task spec lists "Create the `docs/interfaces/` directory with a placeholder `.gitkeep`" alongside generating the three interface files in the same directory. With `proto.md`, `schema.md`, and `rust-api.md` all present, `.gitkeep` is redundant — git only tracks files, not directories, so the three generated files already keep the directory live. Skipping the placeholder avoids a stale file that would need to be cleaned up later. If the operator wants strict spec-compliance, adding an empty `.gitkeep` is one `touch` away.
  - **Implemented in bash + awk, not Rust.** The task spec offers either; bash is sufficient here because the workspace currently has zero `.proto` files, zero migrations, and zero `api.rs` files (Phase 0). The awk parsers handle the canonical forms (proto messages/services/enums with bodies, single-line and multi-line declarations, tuple/unit structs, multi-line SQL `CREATE TABLE` blocks, single-line `CREATE INDEX`). Verified by running against a synthetic `/tmp/regen-test/` fixture with all three formats; output is correct. The first task to add real proto / migration / `api.rs` content (Tasks 06, 09, and whichever lands an `api.rs` first) will exercise the parsers for real and may surface edge cases.
  - **Awk regex-arg gotcha resolved.** First implementation passed `/\{/` as a function argument to `count(s, c)`; in awk a regex literal in a value context evaluates to the boolean result of matching `$0`, not a pattern — so `count("message Workspace {", /\{/)` returned 0 (no match against `$0`) instead of 1. Replaced with dedicated `n_open(s)` / `n_close(s)` helpers (and `n_lparen` / `n_rparen` in the SQL block) where the regex literal lives inside the function. Lesson captured here so future generators don't repeat it.
  - **`# shellcheck disable=SC2016` applied file-wide.** Several `printf` format strings embed literal markdown backticks (e.g. `'## \`%s\`\n\n'`). shellcheck reads those as shell expressions and emits info-severity SC2016. They're not shell expressions — they're markdown — so the file-level disable is correct. With the directive, `shellcheck scripts/regen-interfaces.sh` exits 0.
  - **CI step is matrix-conditional, not a separate job.** Added the interface-check step into the existing `build` job with `if: matrix.os == 'ubuntu-latest'`, matching "as a CI step in `.github/workflows/ci.yml` (Linux only)". A separate job would also work but would re-checkout, re-cache, and double the YAML; the matrix-conditional is one step and cheaper.
  - **Verification step 4's "add `pub trait Foo {}` to `src/lib.rs`" is treated as a typo for `src/api.rs`.** The "Public interface this task locks" section is explicit: "every crate's pub-facing module is at `crates/<crate>/src/api.rs`". The script intentionally does NOT look at `lib.rs`. Verified the parser by temporarily writing `crates/error/src/api.rs` with a single-line `pub trait FakeTrait {}`, a tuple `pub struct Tuple(pub u32);`, and a multi-line `pub trait Multi { ... }`; the regenerated `rust-api.md` captured all three correctly. File deleted before commit.
- **Open questions for next task:**
  - The `api.rs` convention is now locked. Tasks that want a symbol to be part of the "public surface" must put it in `crates/<crate>/src/api.rs` and re-export from `lib.rs`. If a crate's pub items live elsewhere, they're invisible to the generator (and therefore invisible to drift checks). Task authors should declare in their task file whether they're publishing through `api.rs`.
  - Proto parsing handles top-level `message`/`service`/`enum`. Nested messages (a `message` declared inside another `message`) and `oneof` blocks aren't called out specifically but should fall through the brace-balance counter correctly — nested declarations end up inside the outer block's code fence and are not separately ToC'd. Task 07 (first real proto messages) will be the first real test.
  - SQL parsing handles `CREATE TABLE` and `CREATE INDEX`. Trigger/view/virtual-table forms aren't captured. Task 09 will only have tables and indexes per the design, so this should be fine; revisit if Phase 3 adds triggers.
