## Goal
Make the Iroh transport **actually live on a booted Core**. Tasks 212 (the `crates/transport` endpoint + `serve_iroh`) and 217 (the `TransportHandle` façade) built and froze the spine but both **explicitly deferred wiring it into the boot actor** — so today `concerto_core::api_server::serve_iroh` is called from exactly one integration test (`crates/core/tests/transport_iroh.rs`) and **never from `boot.rs`**, and `boot.rs` installs a `NoopSessionCloser` with a comment saying "Task 217's TransportHandle replaces this one-liner." The result: a Core booted by the daemon/embedded path listens **only on UDS**; there is no live Iroh listener to dial, no Core-side responder for the dedicated Noise-XX **pairing channel** (transport channel-tag `0x03`), and revocation cannot tear down remote sessions. This blocks Task 220's split-host capstone smoke **and** the Phase-2 Tier-3 manual checklist ("pair a real second machine over LAN", "pair from a real remote network", "revoke a device and confirm <60s stream teardown"), all of which require the transport to be live. This task closes that gap: boot brings up `serve_iroh` (config-gated), a Core-side pairing responder accepts the `0x03` channel and completes pairing via `PairingCoordinator`, and the real `TransportHandle`-backed `SessionCloser` replaces the no-op so revoke severs Iroh sessions.

## Scope — in
- **Boot-time Iroh listener.** In `boot.rs`, when (a) a keychain-backed Core identity exists, (b) `managed.json` `remote_disabled()` is false, and (c) Iroh serving is enabled (a config/env opt-in — default **off** in V1.0 so the existing UDS-only boot smoke is unchanged; e.g. `CONCERTO_ENABLE_IROH=1` or a `managed.json`/runtime-config field — pick one, document it, freeze the name), construct the Core's Noise X25519 static (derive + persist its 32 bytes; reuse the keychain via a new `SecretKind`-or-`CoreSecretSlot`-style slot, or `concerto-identity`'s key tooling — keep it distinct from the Ed25519 identity, per Task 208/212), build the `IrohTransport`/`TransportHandle`, and spawn `serve_iroh` feeding the **shared** `CoreServiceSet` (identical handlers to UDS, with the `ConnTransport(Iroh)` tag). Run it as a supervised sibling of the UDS server under the same shutdown token; clean teardown on shutdown (no leaked endpoint).
- **Core-side pairing responder.** Accept the transport's `0x03` Pairing channel (`PairingListener::accept()` from 212/217), run the **Noise XX responder** over the one-shot token, drive the `PairingCoordinator` to verify the device's signed `PairingRequest` and mint a `SignedDeviceCert`, and return it to the device — the responder half of 207's exchange, now over the real Iroh channel instead of the test `duplex`. Honor the token TTL/one-shot/≤3-active rules already enforced by the coordinator. Audit via the existing `DevicePairing*` kinds.
- **Live `SessionCloser`.** Replace `NoopSessionCloser` in `boot.rs` with an adapter backed by `TransportHandle::close_sessions_for_device` (via the 217 `DeviceId` `From<[u8;32]>`), so `DeviceManager::revoke_device` actually severs the revoked device's open Iroh sessions (the 209/210 revoke→teardown contract).
- **Expose the listener's address for clients/tests.** Make the booted Iroh endpoint id (and the Core's Noise public key) queryable/loggable so a client (Task 220's smoke driver, the Desktop) can dial it — e.g. surface via the existing `Runtime`/`Devices` `GetCoreInfo`/logs, or a boot-returned handle field. Do not invent a new public RPC if an existing one suffices.
- **Tests (Tier 2, loopback, relays disabled):** extend `crates/core/tests/transport_iroh.rs` (or a new `crates/core/tests/iroh_boot.rs`) to: boot a Core with Iroh enabled (keychain-isolated via `CONCERTO_KEYCHAIN_SERVICE`), have a second in-process Iroh endpoint **pair over the `0x03` channel** and receive a cert, then make an **authenticated** `GetServerCapabilities` asserting `transport_kind == IROH`, and a `RevokeDevice` that tears the session down. All waits timeout-bounded; no leaked processes.

## Implementation notes
- Keep the Iroh spawn **opt-in and non-default** so every existing smoke check + the daemon's default behavior is byte-unchanged; 220's smoke flips the toggle. This avoids regressing the 16-capability smoke suite.
- The Core Noise X25519 static: it must persist (so a Core keeps its identity across reboots) and is distinct from the Ed25519 signing identity (208/212). Reuse the keychain (a new slot) or the Core's data dir; freeze the storage location. Best-effort/timeout-bounded keychain access (mirror Task 206's pattern) so a keychain-less/headless env degrades gracefully rather than hanging.
- The pairing responder is a supervised task that loops on `PairingListener::accept()`; one accept == one pairing attempt == one `0x03` bidi stream (212's channel model). Bound it with the coordinator's TTL.
- Reuse `serve_iroh` + `CoreServiceSet` exactly as `transport_iroh.rs` does — do not duplicate the service-registration graph; factor if needed but prefer calling the shipped builder.
- **Keychain-in-CI hazard:** any test that boots a Core must set `CONCERTO_KEYCHAIN_SERVICE` to a unique value first (see `crates/core/tests/embedded_boot.rs`); the shared `concerto-test-harness` already self-isolates.
- Cross-platform: must build on the Windows + Linux lanes (iroh is cross-platform; the lockfile's `wmi`→`windows 0.62.2` alignment must not regress).
